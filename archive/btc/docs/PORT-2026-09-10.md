## Protections added

- **SELL funnel** — symmetric short side (20-bar ceiling, upper-wick rejection, falling EMA50 slope, close near/below EMA50). RSI window mirrors BTC's 40–70 to **30–60**.
- **Regime gates** — EMA50 slope vs 30 bars ago + entry within 0.3×ATR of EMA50, both directions. `ema50_history` seeds from the log on restart so the gate works immediately.
- **Daily-loss circuit breaker** — `MAX_DAILY_LOSSES = 3` (UTC day), surfaced on the dashboard with a HALTED badge.
- **Escalating SL cooldowns** — 30 min after 1 SL, 60 min after 2 consecutive SLs. (The old `analyze_recent()` rule is kept in code but disabled — superseded.)
- **Expanded blackouts** — London 07:55–09:00, NY pre-market 12:25–12:45, NY/macro 13:25–15:15 UTC.
- **16-field ledger + self-healing migration** — `Trade_Type` column, `migrate_trades_csv()` on start + before every append (backup kept), loud drift tripwire in `trade_filter.load_recent_trades()`.
- **`DATA_SOURCE=MT5` option** — Wine sidecar (`tools/mt5_feed.py`, M5/BTCUSD defaults) + `deploy/mt5feed.service` (install as `mt5feed-btc`) + `run_mt5_test()` with restart dedup. Same stale guard.
- **LIVE mode hardened** — SELL order support, M5 closed-candle polling with dedup (previously re-evaluated the same candle), numbered live trades, status save after fill.
- **Dashboard** — dual Buy/Sell funnel telemetry, trade-direction badge, daily-loss tracker, next-trade number, entry context. Same port 6001.
- **Tooling** — `check_data.py` (integrity gate), `validate_gates.py` (gate replay), `phantom_trades.py` (blocked-signal counterfactuals), `smoke_test.py` (8 scenarios, all passing), `autosync.sh` (data sync + smoke-gated deploy). Data files (`trades.csv`, `skipped_trades.csv`) are now tracked in git so reviews can happen from the repo.
- **Docs** — `README.md`, `archive/PROJECT_LOG.md`, this file. Retired `generate_trades.py` → `archive/` (its params didn't match the engine and it overwrote the ledger with `mode="w"`).

## Deliberately NOT ported / adapted for BTC

| Gold behavior | BTC decision | Why |
|---|---|---|
| 21:45–22:30 UTC rollover blackout | Skipped | Forex rollover spread spike; BTC has no rollover |
| `is_market_quiet()`: no alerts 21:00–02:00 UTC + weekends | Always returns `False` | BTC trades 24/7 — any silence is an incident |
| M1 candles | Kept **M5** (`CANDLE_SECONDS=300`) | BTC bot is intentionally medium-term; current log is M5 cadence |
| Absolute ATR bounds ($1.10 / $4.50) | Kept **%-based** bounds (0.01% / 0.60%) | Adaptive to BTC price; absolute $ values would rot |
| RR 1:1.5, RSI 30–68, wick 0.38 | Kept BTC's RR 1:2, RSI 40–70, wick 0.15 | Strategy params are BTC-native; no BTC data justifies changing them yet — recorded as review items in `PROJECT_LOG.md` |

| `check_data.py` gap >5 min, entry ±2 min | Gap >15 min, entry ±6 min | M5 log spacing |
| Phantom P&L $1/point | Scaled × `LOT_SIZE` 0.01 | Match the engine's simulated sizing |
| `status.json`/`trades.csv` baselines $500 | $200 (`STARTING_BALANCE`) | Matches the real account size |

## Honest caveats (same as gold's)

- The regime gates and SELL mirrors are **inherited hypotheses, unproven on BTC**. Gold validated them on n=37–41 gold trades; BTC has no reviewed trades yet. First `docs/REVIEW-*.md` should re-validate rather than assume.
- `archive/forward_test_log_m1.csv` (8,537 M1 rows) predates the M5 design — do not mix it with M5 data in any analysis.
- `SYMBOL_MT5` (`BTCUSD` vs `BTCUSDm`) and XM's BTC contract size are still unverified — LIVE mode must not run until confirmed.

## Deploy notes

After pulling: restart the engine. It resyncs stats from `trades.csv` (migrating the schema if needed), restores any open trade, and seeds the slope gate from the log. Verify the broker symbol in MT5 Market Watch before enabling `DATA_SOURCE=MT5` (`MT5_FEED_SYMBOL` override exists for `BTCUSDm`). Suggest adding `Environment=PYTHONUNBUFFERED=1` to the engine's systemd unit so prints reach the journal unbuffered (gold 2026-09-10 lesson).
